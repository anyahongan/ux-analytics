# UX Analytics Pipeline

This repository captures the final public version of a multi-stage UX analytics pipeline that was developed iteratively across several working commits before being consolidated for portfolio review. This repository exports UX session data from Azure Table Storage, parses and standardizes it, calculates UX metrics, builds reports, and validates the analytics pipeline.

## Project structure

- `data/raw/` — Azure exports
- `data/parsed/` — standardized data and calculated metrics
- `reports/current/` — reports from the latest successful run
- `reports/archive/` — reports from previous runs
- `config/` — non-secret configuration and run metadata

## Workflow

1. Log into Microsoft Azure.
2. Confirm new intake data exists.
3. Activate the virtual environment.
4. Run `python complete_ux_metrics.py`.
5. Review `ux_validation_report.xlsx` for any pipeline issues.
6. Review `ux_report.xlsx` for UX findings.
7. Share or archive the generated reports as needed.

## Azure Access Requirements

The UX Analyst will require access to Microsoft Azure. From there, the individual should be granted viewing access to a Storage Account (type) found in a defined resource group.

Upon entering this Storage Account, refer to the left-hand sidebar, which lists items such as "Overview", "Activity log", "Tags", and more. The user should refer to "Storage browser" > Tables > and their desired Table Name. This table lists multiple properties which may include strings, DateTimes, and Booleans. Properties may include "PartitionKey", "RowKey", "Timestamp" and more. 

## Pipeline Overview

The analytics pipeline consists of five scripts that execute automatically through `complete_ux_metrics.py`.

1. export_raw_data.py
   Downloads the latest Azure Table Storage data.

2. parse_ux_data.py
   Standardizes raw records into sessions, events, and fields.

3. build_ux_metrics.py
   Calculates session-level and question-level UX metrics.

4. build_ux_diagnostics.py
   Generates the UX report workbook.

5. validate_ux_pipeline.py
   Performs validation checks to confirm the pipeline completed successfully.

## Running the Analysis

When running the analysis, the UX Analyst has the option to filter intakes by date and time. Below are three examples of prompting the pipeline to use (1) All Azure data, (2) Data filtered by UTC date range, (3) Data filtered by UTC time range. To align with the timestamps visible on Azure, the pipeline also uses UTC.

 ```powershell
python complete_ux_metrics.py
```

 ```powershell
python complete_ux_metrics.py `
  --start-date 2026-07-22 `
  --end-date 2026-07-22
  ```

 ```powershell
  python complete_ux_metrics.py `
  --start-time "2026-07-22 21:00" `
  --end-time "2026-07-22 22:00"
  ```
  
The pipeline performs the following steps:

1. Exports the latest records from Azure Table Storage.
2. Updates the raw master workbook.
3. Parses and standardizes session, event, and field data.
4. Applies the selected UTC analysis window.
5. Calculates UX metrics.
6. Archives the previous reports.
7. Generates the current UX report.
8. Validates the completed analytics pipeline.

## Outputs

The primary outputs are saved in:

- reports/current/ux_report.xlsx
- reports/current/ux_validation_report.xlsx

Supporting data files are saved in:

- data/raw/master_raw.xlsx
- data/parsed/master_parsed.xlsx
- data/parsed/ux_metrics.xlsx

When the pipeline is run again, the previous current reports are moved automatically to reports/archive/.

## Report Guide
### UX Report

Location: reports/current/ux_report.xlsx

The UX Report is the primary deliverable generated by the UX Analytics Pipeline. There are 11 sheets total:

1. Executive Summary: Provides a high-level overview of the analysis, including session volume, completion rates, and key findings.
2. Friction Ranking: Ranks questions by frictionScore, which is flagged by negative behavioral signals.
3. Drop-off Analysis: Provides dropoffPercent for questions that were left incomplete and the session did not end.
4. Backtracking Analysis: Provides repeatIntensityPercent for questions that were most frequently revisited.
5. Outlier Sessions: Identifies individual sessions that were flagged for unusual behavior.
6. Form Comparison: A high-level overview to compare UX metrics across different intake forms.
7. Summary Metrics: A high-level overview of quantitative metrics for timing, completion, and statistical analyses.
8. Session Summary: Identifies individual sessions and their completion time, repeats, eventPath, and more.
9. Question Summary: Indentifies individual questions for a high-level comparison of metrics between questions.
10. Session Paths: Indentifies individual session paths; specifically the order in which they complete the questions.
11. Methodology: Defines metrics used in this sheet, their calculation, and how users should interpret them.

### Validation Report

Location: reports/current/ux_validation_report.xlsx

The Validation Report verifies that the UX Analytics Pipeline was completed successfully and that the generated contents are reliable for analysis. There are 5 sheets total:

1. Validation Summary: Defines critical validation metrics, their values, and how the user should interpret them.
2. Session Issues: Identifies issues flagged, their severity, description, and reccomended action by individual session.
3. Event Issues: Identifies issues flagged within event data, their severity, description, and reccomended action.
4. Field Issues: Identifies issues flagged, their severity, description, and reccomended action by individual field.
5. Question Warnings: Identifies warnings, such as 'low sample size', their severity, description, and reccomended action by question.

### Parsed Data

Location: data/parsed/master_parsed.xlsx

This Excel Sheet contains the standardized version of the raw Azure export. There are 5 sheets total:

1. Raw Data: The raw extraction of data collected from the Azure table.
2. Sessions: The completion time of each submission. 
3. Events: The order in which each question was logged by submission.
4. Fields: Changes that occurred in each question, by submission.
5. Data Quality: Records data-processing issues such as invalid JSON, missing timestamps, duplicate IDs, and more.

This sheet also uses new variables, including:
- shortIntakeId: Captures all characters until the first dash of intakeId
- shortRowKey: Captures all characters until the first underscore of RowKey
- sourceRow: The row number from master_raw.xlsx starting from Excel row 2
- eventOrder: The position of each event within that submission's eventsJson list, starting at 1
- fieldId: The key assigned to each field inside fieldsJson
- completionSeconds: submittedAt - startedAt
- completionMinutes: completionSeconds / 60

### UX Metrics

Location: data/parsed/ux_metrics.xlsx

This Excel Sheet contains the calculated metrics used in the final UX Report. There are 4 sheets total:

1. Summary Metrics: Records terms, values, and definitions used in the final UX Report.
2. Session Summary: Records completion times, repeat events, eventPath, and more metrics.
3. Question Summary: Records metrics of total records, repeats, changes, and more per question.
4. Session Paths: Records the order in which different submissions complete the questions presented.

Generated variables for this sheet include:

- field: The Azure property where the issue was identified
- issueType: The category of data quality issue deteched
- details: Additional information describing the detected issue

## Repository Maintenance

When making changes to the analytics pipeline:

1. Update the relevant Python script(s).
2. Update this README if the workflow or outputs change.
3. Test the pipeline using a small Azure data sample.
4. Confirm that both the UX Report and Validation Report generate successfully.
5. Commit and push the changes to GitHub.

Note: UX metrics should always be interpreted within the context of sample size. Small deployments or pilot studies may produce directional insights but should not be treated as statistically representative until sufficient user data has been collected.
